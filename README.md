# 玉堤小学校バス通過 LINE通知

毎朝 6:00〜6:40 の間、東急バス「玉11」系統（二子玉川駅→多摩川駅）が
「玉堤小学校」停留所を通過したら LINE に通知します。GitHub Actions で無料で
毎日自動実行する構成です。

## 仕組みと、事前に確認できたこと

- 監視対象ページ: `https://tokyu.bus-location.jp/blsys/navi?EID=nt&RAMK=55&SCT=1&VID=rtl`
  （東急バスナビ「玉11」二子玉川駅～多摩川駅の路線別運行情報。玉堤小学校はこの
  区間で二子玉川駅から5番目の停留所です）
- このページは JavaScript なしでも、取得のたびに最新のバス位置がサーバー側で
  描画された HTML が返ってくることを確認済みです（ページ内の「◯◯時点の情報」
  という表示時刻が、取得するたびに更新されます）。そのため Playwright などの
  ブラウザ自動化は不要で、`requests` によるシンプルな HTTP GET だけで動作します。
- ページ内では停留所名が二子玉川駅→多摩川駅の順に並んでおり、運行中のバスが
  いる区間には「バスアイコン＋『多摩川行』などの方面表示」が停留所の間の行として
  挿入されます。これは実際に稼働中のバス表示（同時に2台运行していた実データ）で
  確認済みのパターンです。
- 判定ロジック（`check_status()`）は「玉堤小学校よりページ内で後ろに、同方向の
  バスマーカーがあるか」を見ているだけの、HTMLテキストの出現順を利用した
  ヒューリスティックです。`test_logic.py` に、実際に観測した構造を模した
  オフラインテストを用意してあり、実行して正しく動くことを確認済みです。

  ```
  python test_logic.py
  ```

- **これは公式APIではなく、公開ページの表示パターンを解析した非公式な方法です。**
  サイトがリニューアルされると判定が壊れる可能性があります。壊れた場合は
  「一度も判定に成功しなかった」ことを示す警告LINEが届くようにしてあるので、
  気づけるはずです（`bus_notify.py` 内のコメント参照、調整方法は下記）。

## セットアップ手順

### 1. LINE公式アカウント + Messaging API を用意する

LINE Notify は2025年3月に終了しているため、後継の LINE Messaging API を使います。
無料枠は月200通まで（このスクリプトは1日1通なので十分収まります）。

1. [LINE Official Account Manager](https://manager.line.biz/) で公式アカウントを
   新規作成する（個人利用でOK、無料）。
2. 作成したアカウントの管理画面で「設定」→「Messaging API」→
   「Messaging APIを利用する」を有効化する。
3. 表示されるリンクから「LINE Developers」コンソールに移動し、自動生成された
   チャネルを開く。
4. 「Messaging API設定」タブの一番下にある「チャネルアクセストークン（長期）」を
   発行する。この値を後で `LINE_CHANNEL_ACCESS_TOKEN` として使います。
5. スマホの LINEアプリで、作成した公式アカウントを友だち追加する
   （Official Account Manager のホーム画面にQRコードがあります）。
6. 通知は `broadcast`（友だち全員への配信）で送る実装にしてあります。友だちが
   自分だけなので、実質「自分専用の通知チャネル」として使えます。これにより
   ユーザーIDの取得という面倒な手順が不要になっています。

### 2. GitHubリポジトリを用意する

1. GitHubで新しいリポジトリを作成する（**Public推奨**。Privateでも動きますが、
   GitHub Actionsの無料実行時間には月間の上限があります。Publicなら無料枠を
   気にする必要はありません）。
2. このフォルダの中身（`bus_notify.py` / `requirements.txt` / `test_logic.py` /
   `README.md` / `.github/workflows/notify.yml`）をそのままリポジトリ直下に
   アップロードする（`.github` フォルダごと、フォルダ構成を保ったままにしてください）。

### 3. Secretを設定する

リポジトリの「Settings」→「Secrets and variables」→「Actions」→
「New repository secret」で以下を登録します。

| Name | Value |
| --- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | 手順1-4で発行したチャネルアクセストークン |

### 4. 動作確認する

- **ローカルで判定ロジックだけ確認**（LINE設定不要、ネットワークがあればOK）:
  ```
  pip install -r requirements.txt
  python bus_notify.py --once --debug
  ```
  実行時刻に関わらず、現在のバス位置から玉堤小学校を通過済みかどうかを1回だけ
  判定して表示します（LINEには送信しません）。早朝以外の時間帯でも、既に
  運行を終えた日中〜夜のバスで動作の雰囲気を確認できます。

- **LINE通知まで含めた本番動作の確認**: GitHubリポジトリの「Actions」タブ →
  「玉堤小学校バス通過LINE通知」→「Run workflow」で手動実行できます
  （`workflow_dispatch` を設定済みなので、6時を待たずに試せます）。
  実行後、通過判定が True であれば実際にLINEへ届きます。

  ※ 早朝以外に手動実行すると、その時点で対象区間にバスが走っていない限り
  「不通過」判定になりLINEは届きません。これは正常な動作です。

以降は毎朝 05:55 JST に自動起動し、6:00〜6:40 の間に通過を検知した時点で
1回だけ通知が届きます。

## カスタマイズ

- **平日のみにしたい場合**: `.github/workflows/notify.yml` の cron を
  `"55 20 * * 0-4"` に変更してください（UTC日曜〜木曜 = JST月曜〜金曜朝）。
- **監視時間帯を変えたい場合**: `bus_notify.py` の `WATCH_START` /
  `WATCH_END` を変更し、あわせて `notify.yml` の cron 開始時刻も調整してください。
- **チェック間隔を変えたい場合**: リポジトリSecretまたはワークフローの `env` に
  `POLL_INTERVAL_SEC`（秒）を追加してください（デフォルト30秒）。
- **対象停留所や系統を変えたい場合**: `STOPS_IN_ORDER` / `TARGET_STOP` /
  `BUS_PAGE_URL` / `RAMK`（系統コード）を書き換えてください。他系統の
  `RAMK` の値は、東急バスナビで路線を検索した際のURLから調べられます。

## 注意点

- 東急バスの公開ページを解析する非公式な仕組みです。ダイヤ改正やサイト
  リニューアルで動かなくなる可能性があります。
- GitHub Actionsのスケジュール実行は、GitHub側の負荷状況により数分〜
  十数分遅れることがあります（[GitHub公式ドキュメント](https://docs.github.com/actions/using-workflows/events-that-trigger-workflows#schedule)
  にも明記されています）。05:55起動にして余裕を持たせていますが、それでも
  ずれる可能性はゼロではありません。重要な用途では過信せず、時々
  `--once` での動作確認や実際の通知タイミングを見ておくことをおすすめします。
- バスの遅延・運休・臨時ダイヤ等は考慮していません。あくまで表示されている
  リアルタイム位置に基づく判定です。
